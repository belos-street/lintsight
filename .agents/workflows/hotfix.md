# Workflow: hotfix（紧急修复）

> 适用：线上/阻断性故障，需要立即止血。由 `workflow-guide.md` 路由。

## 步骤

1. **确认紧急程度**：是否真阻断（影响范围/可用性）；明确可豁免的流程（spec-first 先行文档、完整评审）。
2. **最小止血**：只改根因相关最小范围；禁止夹带重构、新规则、新功能。
3. **立即验证**：目标复现用例 + 关键路径测试；涉及引擎时确认 fail-open 不吞结果。
4. **提交**：`fix:` 前缀并标注 hotfix；推 dev 分支，按项目发布流程处理。
5. **24h 内补记录**：`docs/changes/<change-id>/` 三层文档补全（背景、根因、止血 vs 根治）；新坑写入 `decisions.md` 或相关文档。
6. **复盘**：按 `memory.md` 三问；需要根治的项登记到 `execution-todo.md`。

## 关键闸门

- 止血改动必须最小，不得引入未验证的行为变更；
- 豁免的是「先行文档」，不是「事后补录」；
- 不得用 `--no-verify` 绕过校验，除非用户明确知情。
