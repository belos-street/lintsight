# 决策记录沉淀规则（Memory）

`.agents/memory/decisions.md` 由 LLM 在对话中**自动维护**，不是只靠人工。

## 一、承接任务前先读

涉及既有约定的任务（目录归属、工具链选型、规则/引擎架构、流程规范）开始前，先读：

- `.agents/memory/decisions.md`
- `.agents/memory/README.md`（引擎边界）
- 相关 `docs/upgrade/v0.1/upgrade-plan.md` 章节

避免推翻既有结论或重复讨论。

## 二、达成决策时主动追加

当对话中**敲定**具有长期约束力的技术/流程决策时，主动追加到 `decisions.md`，无需用户提醒。**普通决策可自动追加；涉及推翻既有决策、改变铁律/边界/契约/流程的，先征得用户确认后再写。** 例如：

- 选用/弃用工具、库、运行时；
- 目录/文件归属、解析器/引擎边界；
- 规则 ID、指纹、契约、默认启用策略；
- 分支/提交/评审流程变更。

### 不需要记录

- 一次性实现细节、临时调试结论；
- 已有且未变化的决策；
- 无长期复用价值的单次指令。

## 三、记录格式

只追加、不覆盖；编号取当前最大值 +1。

```markdown
## Dn · 决策标题

- **结论**：……
- **理由**：……
- **Supersedes**：Dn（可选；仅当本决策替代旧决策时写）
- **日期**：YYYY-MM
```

被替代的旧决策末尾追加 `> 已被 Dn 替代`，不要删除旧记录。

写入后在回复中简要说明新增了哪条决策（编号 + 标题）。

## 四、复盘三问

每次开发/修复完成后，除新增决策外，还要把教训落回文档：

1. **避免此错需要什么规则？** → 是否补强 spec-first / verification / rule-change。
2. **属于哪个文档/规则？** → `docs/changes/`、`docs/spikes/`、`docs/upgrade/`、`.agents/rules/` 或新决策。
3. **放在哪个位置？** → 工作流步骤 / 已知坑 / 检查清单 / 决策记录；确定后立即写入，不只停留在对话。
